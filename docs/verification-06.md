# Ticket 06 verification

Implementation is present; these checks have **not** been executed on macOS or an iPhone. Windows cannot build SwiftUI, Speech, or the iOS XCTest target. The earlier tickets' device/build checks also remain outstanding.

On a Mac, generate the project with `xcodegen generate`, then run the ExpenseTracker scheme's tests in Xcode on an installed iPhone simulator. `VoiceCaptureSessionTests` covers missing-payment follow-up, spoken full correction, recognition failure and edited retry, cancellation, unfamiliar-source confirmation/write failure, corrupt draft preservation, and stale-draft reconciliation after a successful save whose draft cleanup failed.

## Device checks

1. Open Voice entry and say “I bought a sausage from Indomaret for 15000 rupiah.” It must ask for payment details. Record “QRIS GoPay” as a follow-up. Exactly one expense must save, retaining the same capture identity.
2. Say “Lunch 15000 or 20000 QRIS GoPay.” Nothing must save. Say “correction lunch 15000 rupiah QRIS GoPay yesterday.” One expense must save for yesterday. For unsupported/ambiguous wording, the flow supports a full spoken restatement prefixed by “correction” or “koreksi”; arbitrary isolated amount/date corrections are not promised. Verify typed field correction and explicit Save as well.
3. Say a complete purchase with an unfamiliar payment source. Decline by choosing an existing source in the form and Save, or Cancel. The unfamiliar source must not be created. Repeat and explicitly Add the named source; it must then resolve through the shared source rules. Archived sources and conflicting aliases must not bypass the existing rules.
4. Force a recognition error after some text has appeared (for example, disable connectivity when server recognition is required). No partial result may auto-save. Captured text must remain editable; Retry must use the edited transcript. If nothing was captured, typing and Record must remain available.
5. Leave an incomplete draft with Keep draft and return, then reopen Voice entry. Its transcript and manual edits must remain, and recording must wait for an explicit button press. Relaunch the app and repeat. Drafts must contribute nothing to History, monthly totals, or yearly totals. Save the draft and confirm the expense contributes exactly once; edit/delete/Undo must update totals normally.
6. Switch to keyboard during recording. Existing recognized text must remain in the draft. Complete the manual fields and Save offline. Cancel must remove the draft without saving an expense. Reopen Voice entry after cancellation and verify the old transcript is absent.
7. Simulate local storage failure. The draft must remain editable and no Saved confirmation may appear. Restore storage and retry Save; there must be exactly one record. Run the automated cleanup-failure test to verify that a saved expense with a stale draft is reconciled by capture ID on relaunch.

Draft text is retained only in the single local `voice-draft.json` file until save or explicit Cancel; expenses contain no transcripts. This is durable local app storage, not an audio/transcript archive. The app never stores an audio file. If draft loading fails, the file is preserved and capture is blocked with an error instead of overwriting it. If draft writing fails, on-screen text remains available with an error but cannot be promised to survive termination. A draft cleanup failure after saving keeps the Saved summary open with a Retry draft cleanup button; returning to the main confirmation waits for cleanup. Reopening reconciles the saved capture ID before accepting another save. Remote recognition retention must be evaluated separately using ticket 05's documentation.
